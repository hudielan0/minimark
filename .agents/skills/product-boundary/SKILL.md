# Product boundary

1. Read `docs/PRODUCT.md`.
2. Restate the proposed user-visible behavior and the user it serves.
3. Map it to an existing first-release promise or identify it as a scope expansion.
4. For in-scope work, write observable acceptance criteria and the smallest vertical slice.
5. For expansion, record the value, added risks, and evidence that it is required; stop for human approval.

Completion criterion: every proposed change is classified as required, supporting, deferred, or rejected, with a product-contract reference and no invented requirement.
